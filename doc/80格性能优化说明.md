# 80×80拼图性能优化

## 编辑器预览启动修复

`temp/logs/project.log` 的实际堆栈显示，最早的错误是 `BarFilled.updateUVs → Sprite.fillStart → RowPrototype.onLoad` 读取空SpriteFrame的 `width`。这中断了onLoad，首页对象尚未创建，后续update才重复报告 `undefined.visible`。

现已将FILLED类型及填充参数的初始化移到SpriteFrame加载成功回调内；渲染时也不在缺少SpriteFrame时设置填充进度，并保护初始化未完成的update/结算入口。`tools/test-initialization.cjs` 用延迟资源回调和严格填充属性复现旧问题并验证修复：资源未到时进入首页/游戏安全、资源加载后自动发射正常。另通过类型检查、首页、4381帧游戏与完整结算回归。需停止旧预览并重新启动以确认编辑器实际运行。

## 渲染优化

问题：旧棋盘6400个Sprite节点在每帧参与场景遍历，每颗豆子归位后又遍历6400格并重新设置颜色。结算时还会创建另一套6400个节点。数字Label原本使用默认无缓存模式，界面每帧重复清空并生成静态Graphics。

改动：

- 静态矩阵用原白豆PNG和原20色色板预合成为800×800透明贴图，约47KB。6400格逐格字节验证通过，没有替换成别的猫图。
- 游戏以一个淡色Sprite显示未完成图，一个垂直填充Sprite从底部显示完成行。只留当前行80个实时豆子Sprite，飞行和击中仍独立运动。完成部分不使用额外Mask。
- 当前行只在变化时更新；一颗归位只写入一格颜色，不再遍历6400格。换排复用这80个节点。
- 结算作品共用同一贴图，只需一个Sprite。
- 游戏数字与文字使用Creator3.8.8的CHAR字符图集缓存，当前行编号缩小节点范围；静态文字、颜色、大小与位置不再重复提交。
- 静态进度条与选色栏Graphics只在状态变化/按压动画时重建；空闲帧不清空重画。
- 模拟层不再为无在途豆的子步骤创建空数组，用已归位计数判断排完成。射速、补位、飞行和回弹时间保持原设定。

同一10秒自动发射CPU场景树检查中，总节点由6837降至519；棋盘实时格由6400降至80，另加两层贴图。这个数字是节点结构统计，不是手机帧率。实际GPU批次、设备帧率和触感仍需要Creator/手机预览确认。
